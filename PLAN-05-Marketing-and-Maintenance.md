## Suggested cadence and measurement

- Before launch: inspect target communities, finish public assets, and complete the GitHub destination checks.
- Launch window: introduce the product on eligible Reddit, X, and LinkedIn destinations. Adapt the message to each audience; launch these six projects separately as they become ready.
- First week: review substantive comments, reproduce reports, answer within the authorised scope, and publish a fix when warranted.
- Following weeks: share a documented improvement or tutorial when there is real new information.

Useful follow-up topics:

- Explain how stale process observations are handled.
- Show the setup for two projects using the same preferred port.

Primary activation: a tester correctly identifies the owning project and completes one deliberate management action. Secondary: false ownership matches and setup completion.

Record only available metrics: platform views and meaningful replies, GitHub/release traffic if accessible, participating tester completions, and reported bugs. Define each completion metric's numerator and denominator. Keep unavailable counts marked unavailable; impressions and stars alone do not demonstrate product use.

## Maintenance and project end

Triage incoming issues by impact, publish tested patch releases on GitHub, document changes, and update dependency/provenance records. Suggested next-version direction: Prioritise import of explicit package-script profiles and better child-process reporting only after identity checks and managed restart are dependable.

Reassess after one release-feedback cycle. Continue with the smallest improvement supported by repeated use; reduce scope if the core task is failing. If support ends, publish a final status, export/recovery instructions where relevant, and an accurate archived repository notice.

The initial project is complete when version 1 is reproducible, code and release are on GitHub, the agreed three-platform launch has verified outcomes (or a documented unavailable venue), and support/maintenance ownership is explicit. Ongoing product maintenance follows that milestone.
