## Read and execute in order

1. Product and differentiation: validate a job, choose substantive new capabilities, and document inspiration/reuse.
2. Design, architecture, and GitHub: define the workflow and storage, prepare the original scaffold, and create each product's separate repository during implementation.
3. Build and improve: implement complete milestones and upload reviewable increments.
4. Validate and release: test the actual product, run a small beta, and verify a versioned GitHub release.
5. Market and maintain: use observed browser controls for the agreed Reddit, X, and LinkedIn launch, then support the release.

Build dates remain unset. Complete the five phases in order using their completion gates. Check the product name and select the GitHub owner and repository URL during implementation. Public release is the intended outcome; the development visibility can be decided during setup.

## What makes the plans substantive

This project specifies three distinct capabilities, improvements to the core experience, a data model and component design, four build milestones, meaningful acceptance checks, a beta task, its own GitHub milestones, and tailored marketing drafts. Each keeps accurate upstream credit and a provenance register. Interface decoration alone is not the evidence of independent value; the implemented user workflow and its development records are.

## Original planning boundaries (historical)

No application is implemented or uploaded by this planning task. No repository is cloned or dependency installed. Social copy is future draft material, not a claim that the products already exist. Real publishing requires the correct user account, final destination, demonstrated feature claims, and the appropriate user authorisation when execution is requested.
